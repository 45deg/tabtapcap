# TabTapCap for macOS

Apple Silicon の macOS 26 以降で、アプリの音声やシステム音声を録音し、文字起こしを編集できる SwiftUI アプリです。ビルドには macOS 26 以降の SDK を含む Xcode が必要です。

```sh
./apps/macos/build.sh
open apps/macos/dist/TabTapCap.app
```

1. 「音声ソース」から起動中のアプリか「システム音声」を選びます。ブラウザを選ぶと、そのブラウザで再生中のタブやウィンドウの音声が対象になります。
2. 「録音を開始」を押します。初回は macOS のシステムオーディオ録音を許可してください。
3. 録音中は、直近10秒の音量の変化と、選択した言語の認識結果が表示されます。音声は録音中に M4A/AAC へ逐次圧縮して保存します。「録音を停止」を押すとファイルを確定し、録音全体から文字起こしを作ります。初回は macOS が選択した言語のモデルを取得する場合があります。音声認識は端末内で行います。
4. 「文字起こし履歴」から音声を再生したり、再生位置を移動したりできます。タイトル・話者・発話・段落の編集、再処理、TXT・WebVTT・JSON の書き出しもできます。「設定」では文章整形を調整し、Apple Speech のモデル状態を確認できます。

録音と編集結果は `~/Library/Application Support/app.tabtapcap.macos/Recordings/` に保存されます。初期の SwiftUI 版で作成した WAV は一覧から再処理できます。Tauri 版の保存先は別で、履歴の移行には対応していません。音声認識の言語は、この Mac の Apple Speech が対応している言語から選べます。話者は手動で設定します。

## 録音と編集の表示

新しい録音のタイトルは「録音 YYYY-MM-DD HH:mm」です。録音開始時のローカル日時を使い、後から変更できます。再処理ではタイトルを維持します。

履歴には録音時間と処理状態を表示します。録音中の文字起こしは暫定結果として表示し、停止後に確定結果へ更新します。

「編集」を押した後、修正する発話を選ぶと、その発話の本文・話者・段落設定を編集できます。話者名の変更と追加は「話者を管理」から行います。変更がある録音にはタイトル横と履歴に「未保存」を表示し、「編集を保存」または ⌘S で保存できます。発話を閉じたり履歴を切り替えたりしても、アプリを開いている間は編集中の内容を保持します。「編集を終了」を押して未保存の変更がある場合は、編集を続けるか破棄するかを選べます。

## 言語とコンテキストメニュー

「設定」の「言語」で表示言語（システム設定に従う／日本語／English）と音声認識の言語を別々に指定できます。アプリ内の表示は切り替え直後に更新します。macOS が提供する共通メニューやシステムダイアログは、OS 側の言語設定に従います。録音タイトルや発話など保存した内容は翻訳しません。

認識言語の設定は次の録音に適用し、録音・文字起こし中には変更できません。録音ごとに言語を保存し、通常の再処理にはその言語を使います。旧バージョンの録音は日本語として読み込みます。日本語以外は認識結果の句読点を保持し、日本語用の読点・文区切りを挿入しません。

文字起こしがない録音は、詳細画面の「文字起こしを作成」から処理できます。すでに結果がある場合は「その他の操作」（…）の「文字起こしを作り直す」を使います。履歴を右クリックしても、これらの操作や「言語を変えて再処理」を選べます。編集途中の録音の再処理・書き出しは、編集を保存するか破棄してから行います。発話を右クリックするとコピー、その位置からの再生、発話の編集ができます。

## 音声の保存形式

新しい録音は macOS 標準の Audio Toolbox で M4A/AAC にストリームエンコードします。48 kHz、ステレオは目標 96 kbps（モノラルは 64 kbps）で、実際の容量は音声内容やエンコーダーの動作によって変わります。長さに比例する一時 WAV や音声配列は作りません。ライブ認識は圧縮前の PCM、停止後の文字起こしと再生は保存済みの M4A を使います。既存の WAV は変換せず、そのまま読み込み・再生・再処理できます。

書き込みエラーを検出すると録音を停止し、エラーを表示します。正常停止時にはエンコーダーの残りのデータを書き出し、M4A の管理情報を確定します。強制終了や電源断では確定処理を実行できず、途中の M4A を復旧できない場合があります。

音声テストでは、生成した PCM を使って停止前のディスク書き込み、44.1/48 kHz 入力、モノラル／ステレオ、AAC の再読み込みと再生準備、旧 WAV との混在、ファイルサイズ上限による書き込み失敗を検証します。テストプロセスには macOS の音声エンコーダーを利用できる実行環境が必要です。

## 長時間録音と履歴のメモリ使用

ライブ表示は直近 4,000 文字・最大 40 発話に制限します。認識途中の発話は同じ時間範囲の表示を置き換えます。この制限は表示用で、停止後の確定処理では録音全体を文字起こしします。

履歴一覧は小さな `.index.json` を読み込み、文字起こし本文は選択時、編集時、コピー・書き出し・再処理時に読み込みます。選択を外した本文は保持せず、未保存の下書きとその比較元だけを編集終了まで保持します。読み込みはバックグラウンドで直列に行い、キャンセルされた選択要求や古い読み込み結果を反映しません。

旧バージョンの履歴には初回のみ 1 件ずつ索引を作成します。本文の更新日時・サイズが索引と異なる場合は再生成し、索引の書き込みに失敗しても本文を正本として扱います。本文が壊れた録音はエラー表示し、他の履歴は引き続き利用できます。

`test.sh` には、10 万回のライブ更新、本文を開けない状態での一覧表示、旧形式の索引生成・無効化、選択キャンセル、編集保持、1,000 件・本文約 132 MB の履歴を使う回帰テストも含みます。

## 保存・整形と再生表示の処理

本文の保存、TXT・WebVTT・JSON の生成と書き込み、認識結果の文章整形は、履歴読み込みと共通の actor で直列実行します。処理中も UI のメインスレッドを占有せず、保存・書き出し中は重複操作と終了を防ぎます。保存に失敗した場合は下書きを保持し、再試行できます。保存中に履歴を切り替えても選択は維持し、保存開始後に変わった下書きは削除しません。

再生位置は再生バーと発話の背景だけが監視します。文字起こし本文と編集欄は100msごとの位置更新を監視せず、変更のない発話行は文字分割とレイアウト入力の再評価を省きます。一時停止・再生終了・詳細画面を閉じた後は位置のポーリングを停止します。

`test.sh` は保存待ち中の選択切り替え・二重操作・下書き更新、保存失敗と再試行、バックグラウンド整形・書き出し、再生状態と位置の変更通知の分離、長い Unicode 本文の分割も検証します。画面描画の回数や実録音中のCPU使用率は、このテストでは測定しません。
